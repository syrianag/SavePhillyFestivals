1) System Snapshot

Application

Next.js web platform for public festival discovery, producer submissions, and editorial administration with role-based controls.

Automation

Dedicated N8N runtime and contract-tested workflows, intentionally isolated and controlled from core web release paths.

Release of application code does not automatically activate outbound providers. External integrations require explicit authorization and checklist completion.

3) Workflow Governance

Editorial state model

  • Private states remain non-public until explicit publication.
  • Approval records editorial acceptance only.
  • Cancellation preserves public reference page with protective behavior.
  • Archive acts as terminal, non-destructive historical state.

Data safety characteristics

  • Visitor schedule persistence is browser-local and non-account based.
  • Producer contact details remain private and excluded from public payloads.
  • Transition and moderation actions maintain immutable audit lineage.

5) Operational Playbook

Before production launch

  1. Finalize legal copy for privacy and terms pages.
  2. Verify quality gates including browser coverage on Chromium, Firefox, and WebKit.
  3. Confirm role ownership with organizational aliases and escalation paths.
  4. Complete each provider-specific activation checklist and controlled test.
  5. Record activation decision and rollback owner for each integration.

Incident response baseline

  • Treat moderation safety, personal data concerns, and credential exposure as dual-track escalations.
  • Preserve evidence and avoid destructive cleanup during active incidents.
  • Use retry workflows for transient outbound delivery failures.
